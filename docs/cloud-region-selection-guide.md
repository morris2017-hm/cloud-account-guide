# 阿里云、腾讯云国际版地域怎么选

拿到阿里云或腾讯云国际版账号后，第一台机器开在哪里，往往比买什么配置更影响体验。地域一旦选定，实例本身不能直接「搬家」，换地域基本等于重新部署。所以这一步值得多花十分钟。本文不列具体价格和延迟数字（它们随时间、线路和运营商变化），只讲判断方法，地域清单和价格请以 [阿里云国际版地域列表](https://www.alibabacloud.com/help/en/ecs/regions-and-zones) 与腾讯云国际版控制台为准。

## 先搞清楚几个概念

- **地域（Region）**：一个地理区域，比如中国香港、新加坡、日本（东京）、美国（硅谷）。不同地域之间网络、价格、可售规格都可能不同。
- **可用区（Zone）**：同一地域内电力和网络相互独立的机房。同地域不同可用区之间走内网，延迟很低，适合做主备。
- **内网互通**：同一账号、同一地域内的资源通过私网通信，一般不产生公网流量费；跨地域通信则要走公网或专门的跨地域互联产品，成本和复杂度都会上升。

所以一个基本原则是：**相互频繁通信的服务（应用、数据库、缓存）放在同一个地域。**

## 第一步：看你的用户在哪里

地域选择的第一依据永远是「谁在访问」。

| 主要用户 | 常见优先考虑 | 说明 |
| :--- | :--- | :--- |
| 中国内地用户，但不想或不能备案 | 中国香港，其次日本、新加坡 | 离内地近，且香港及海外地域一般不涉及 ICP 备案；具体线路质量建议实测 |
| 东南亚用户 | 新加坡，或用户所在国家的本地地域 | 阿里云、腾讯云在东南亚都有多个地域，可按目标国家就近选 |
| 日韩用户 | 日本（东京）、韩国（首尔） | 就近原则 |
| 北美用户 | 美国西部（硅谷）或美国东部（弗吉尼亚） | 按用户集中在东海岸还是西海岸选 |
| 欧洲用户 | 德国（法兰克福）、英国（伦敦） | 涉及欧盟用户数据时，同时考虑合规要求 |
| 全球分散 | 源站选一个中心地域，前面加 CDN | 不必每个地区都开服务器，静态内容交给 CDN |

不确定时，先在两三个候选地域各开一台最低配的按量付费实例，用真实用户所在网络去测，测完就释放，花费通常很小。

## 第二步：要不要中国内地地域

国际版账号也能买中国内地地域的资源，但有两个门槛：

1. **身份验证**：阿里云国际版购买中国内地地域资源前需要先完成账号身份验证，见官方 [Account verification overview](https://www.alibabacloud.com/help/en/account/account-verification-overview)。
2. **ICP 备案**：在内地地域对外提供网站服务，需要办理 ICP 备案。

如果你的业务面向海外，或者只是想尽快上线一个对内地用户也能访问的站点，香港及海外地域通常更省事。如果你确实需要内地地域，用国内中国站账号往往更顺，具体区别可以看 [阿里云国际版和中国站的区别](https://www.yundaxian.com/article/aliyun-international-vs-china-site-differences)。

## 第三步：线路和网络类型

同样是香港，不同线路的体验差别可能很大。选购时留意：

- **BGP 多线 vs 精品线路**：部分地域提供面向中国内地优化的精品线路，价格更高。普通 BGP 线路便宜，但晚高峰到内地的质量不一定稳定。
- **按流量 vs 按带宽计费**：访问量小、波动大的业务适合按流量；流量大且平稳的业务按固定带宽更好预估。阿里云国际版按流量计费的 BGP 出流量每月有 CDT 免费额度，海外地域和内地地域分开计算，详见 [CDT 免费流量](aliyun-international-cdt-free-traffic.md)。
- **IP 段与用途**：做跨境电商、广告投放、第三方 API 对接时，有些平台对 IP 所在国家敏感，地域要和业务所在市场匹配。

## 第四步：成本和库存

- **不同地域单价不同**：同一规格在香港、新加坡、美国、欧洲的价格可能差不少，下单前在控制台价格页逐个比较，别凭印象。
- **规格库存**：热门地域的某些规格、GPU 实例偶尔会缺货，选型时准备一个备选规格或备选可用区。
- **流量费常常比机器贵**：对外传输数据多的业务，比较地域时要把流量单价算进去，而不只是看实例月费。

## 第五步：合规与数据所在地

处理个人信息、支付数据或受监管行业的数据时，数据存在哪个国家可能有法律要求（例如欧盟用户数据）。这一步请以你自己的法务或合规判断为准，云厂商只提供地域，不替你判断是否合规。

## 选错了怎么办

实例不能直接改地域，但可以迁移：

1. 在原地域给系统盘做快照，制作自定义镜像；
2. 使用控制台的「复制镜像」功能把镜像复制到目标地域（阿里云 ECS 和腾讯云 CVM 都支持跨地域复制自定义镜像，复制过程可能产生费用）；
3. 在目标地域用该镜像创建新实例，迁移数据库和数据盘数据；
4. 切换 DNS，确认新机器稳定后再释放旧资源。

注意：公网 IP 是跟地域绑定的，迁移后 IP 一定会变，依赖 IP 白名单的业务要提前通知对接方。

## 多地域部署的两个建议

- **一个账号多个地域，还是多个账号？** 同一账号下多地域部署管理最方便，余额和账单统一。如果不同项目需要隔离风险、分开结算，按项目拆分账号会更清晰，账号风控方面的注意事项见 [国际云账号风控与防封清单](cloud-account-risk-control.md)。
- **先单地域跑稳，再扩展。** 大多数小团队一个主地域加 CDN 就够了，过早做多地域只会增加运维和流量成本。

## 账号从哪里来

选好地域的前提是先有一个能长期自己掌控的国际版账号。官方注册通常需要绑定支持的国际支付方式；不方便绑卡的，可以通过 [云大仙](https://www.yundaxian.com/) 办理 [阿里云国际版代开](https://www.yundaxian.com/open/aliyun) 或腾讯云国际版代开，开通后可用 USDT 按账号充值续费（30 USDT 起充）。更多关于地域的说明可参考 [阿里云国际站地域怎么选](https://www.yundaxian.com/article/aliyun-international-region-selection-guide)。

## 一句话总结

先看用户在哪，再看要不要备案，然后实测线路、比较含流量在内的总成本；互相通信的服务放同一地域，选错了就用跨地域复制镜像迁移。
